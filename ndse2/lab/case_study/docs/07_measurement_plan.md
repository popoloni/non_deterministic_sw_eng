# Evaluation plan — separate five endpoints

A local development pilot should record **task time**, **change volume**, **independently accepted patches**, **released/operable changes**, and **business value where measurable** as separate variables. A coding assistant may raise commits while the number of accepted changes or releases barely moves; results in W010 motivate keeping those denominators distinct, but do not validate this case study's metrics.

For a real pilot, preregister eligible brownfield tasks; stratify by task size, engineer familiarity and required checks; compare control / assistance / bounded agent approaches. Record reviewer minutes, test findings, policy violations, rework, human escalations, acceptance, runtime defects and local/cloud costs. Blind verification where feasible. State confidence intervals and missing observations, and do not substitute synthetic demonstration outputs for measured team results.

The `cost_inputs.csv` file is a **blank collection template**, not an estimated ROI. Production economic conclusions in Chapter 12 must wait for observed parameters.
